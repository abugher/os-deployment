This idea seems questionable.  I want to create a duplicate of the LAN
address space on the deployment/testing host, so that each production
system can have a corresponding test VM with the same address, and a
duplicate of the whole set of systems can be tested at once.  (I am
trying to avoid the term "host" except for the system hosting guest
VMs.)

To start, that requires an interface with the same address as the
gateway.  The host should still be able to reach and use the real
gateway, but should also have means to route certain connections through
the local interface with the same address to make SSH connections to
VMs.

I have started work on this, but it is getting confusing.  This document
is being written to try to spell out the whole process in detail, so
that I can see clearly what is working and what is not working, in order
to eventually get it all working - or at least see clearly why it won't
work.


General caveats:  Replies to existing connections can exhibit distinct
behavior from packets establishing a new connection.  Be aware that some
conditions can cause oscillating behavior, so that connections sometimes
work and sometimes do not.
