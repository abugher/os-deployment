PREAMBLE

This idea seems questionable.  I want to create a duplicate of the LAN
address space on the deployment/testing host, so that each production
system can have a corresponding test VM with the same address, and a
duplicate of the whole set of systems can be tested at once.  (I am
trying to avoid the term "host" except for the system hosting guest
VMs.)

To start, that requires an interface with the same address as the
gateway.  The host should still be able to reach and use the real
gateway, but should also have means to route certain connections through
the local interface with the same address to make SSH connections to
VMs.

I have started work on this, but it is getting confusing.  This document
is being written to try to spell out the whole process in detail, so
that I can see clearly what is working and what is not working, in order
to eventually get it all working - or at least see clearly why it won't
work.

General caveats:  Replies to existing connections can exhibit distinct
behavior from packets establishing a new connection.  Be aware that some
conditions can cause oscillating behavior, so that connections sometimes
work and sometimes do not.

See checklist.txt for current status.


CHECKLIST NOTES

VM to VM (other)
________________

This should work.  Each VM should reach another VM when it calls out to
the IP address of a LAN system.

Unimplemented.


VM to LAN
__________

This should not work.  See "VM to VM (other)".


VM to internet
______________

This should work.  The host system should act as gateway, occupying the
gateway address, and performing NAT, so that each VM can reach the
internet by routing through the gateway as defined in inventory.

See certain `iptables` commands.


host to gateway
_______________

This works by default.  Once an interface is assigned the same address,
there is a routing problem.  My first solution is a second routing
table.  The default table routes packets to the real gateway, and the
second table routes packets to the local interface with the duplicate
address.  See the `ip route` commands.

It is also necessary to specify a rule to send marked packets through
the second routing table.  See the `ip rule` commands.

Of course, it is also necessary to mark packets which should go through
the second routing table and thus to the local interface with the
duplicate address.  See certain `iptables` commands which mark packets
from a specific user.

... All of the above is slightly wrong.  Packets are routed THROUGH the
interface, not TO it, at least generally.
